# Аудит стабильности soulm8te 1.2.1

Аудит начат с версии 1.2.0, коммит `2167309`. Проверены сценарии обслуживания DEB, получения и открытия обновлений, навигации в панели OSINT.

| Риск | Что обнаружено | Что исправлено и как проверено |
| --- | --- | --- |
| Высокий | Установщик перемещал бинарник dpkg. После обновления старый `soulm8te-bin` мешал восстановить обёртку и оставался после удаления. | Бинарник остаётся на пути из пакета. Устаревшая копия удаляется. Команда в `/usr/bin` ведёт на проверку sandbox. Тест в изолированном каталоге проверяет миграцию, повторную настройку, обновление, удаление и сохранность сторонней команды. |
| Высокий | Обновление записывалось сразу в «Загрузки». При совпадении имён или ошибке сети готовый файл мог быть повреждён или удалён. | Временный каталог на том же томе, публикация полного файла через hard link, свободное имя при коллизии. Тесты проверяют сохранность оригинала и очистку после неполного ответа. |
| Высокий | Начальный URL мог вести к релизу другого репозитория GitHub. Открытие принимало произвольный путь внутри «Загрузок». | Начальная загрузка ограничена релизами soulm8te. Переходы проверяются по списку HTTPS-хостов. Открытие принимает только пакет, завершённый текущим загрузчиком, с совпадающей SHA-256. Тесты покрывают чужой релиз, недоверенное перенаправление, неверный digest и подмену после загрузки. |
| Средний | Параллельные запросы конкурировали за статус. При отмене или обрыве не все ветки завершали ожидание файла. | Одна активная загрузка на окно, остановка при закрытии окна, таймаут бездействия и единый поток записи. При сетевой ошибке возвращается сообщение, а интерфейс снова позволяет запустить загрузку. |
| Средний | OSINT хранил результат по идентификатору вкладки. Переход в той же вкладке оставлял старый результат. | Панель привязана также к URL. Сквозной сценарий проверяет очистку результата и отключение экспорта после перехода. |

## Границы проверки

- Пакетный жизненный цикл проверяется на копии файловой раскладки в Linux. Обновление на установленной Ubuntu с рабочим столом и AppArmor требует отдельного прогона.
- Сетевые сбои, перенаправления и SHA-256 проверяются на управляемых ответах. Целостность по опубликованному digest зависит от наличия digest в метаданных GitHub.
- Атомарная публикация обновления использует файловую систему с поддержкой hard link. На томах без неё браузер сообщает об ошибке, а пакет доступен на странице релиза.
- Прямой запуск из ярлыка DEB использует бинарник из пакета с установленным `chrome-sandbox`. Команда `soulm8te` в терминале дополнительно проверяет доступность sandbox через обёртку.
