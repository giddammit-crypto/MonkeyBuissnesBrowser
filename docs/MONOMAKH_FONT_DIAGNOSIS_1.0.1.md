# «Мономах» на странице библиотеки: диагностика 1.0.1

Проверка 5 ноября 2026 года. Исходный адрес пользователя: `http://biblioteka33.ru/?p=172`.

## Полученные факты

- Первое обращение к HTTP-адресу через сеть среды вернуло 503 от промежуточного сервера. Повтор через `http://biblioteka33.ru/index.php?p=172` вернул 301 на **HTTP** `http://biblioteka33.ru/?p=172`, затем 200 с HTML. Вариант с `www` также перенаправил на этот HTTP-адрес. Обязательного перехода на HTTPS в этой цепочке не было.
- `https://biblioteka33.ru/?p=172` отдельно вернул 200 с HTML.
- В обоих полученных HTML объявлен `@font-face` с CSS-именем `Monomakh`, весом 400 и источником **`https://biblioteka33.ru/f5/monomakh.ttf`**. Заголовки `.park-heading`, `.park-card-title` и другие элементы используют `Monomakh, Georgia, serif`.
- HTTPS-запрос самого TTF вернул 200, 171584 байта, `Content-Type: application/octet-stream`. В ответе не было `Access-Control-Allow-Origin`. SHA-256 полученного файла: `6dad8920a4550d02b6fc73e06f7b8aa120e5a4abe98e42df820eccd125aee10a`.

HTTP-документ и HTTPS-шрифт имеют разные origin, даже при одинаковом имени сервера. Веб-шрифт с другого origin требует разрешения CORS. Полученная конфигурация HTTP-страницы и заголовков HTTPS-шрифта такого разрешения не даёт. Это не mixed content: здесь HTTP-документ загружает HTTPS-ресурс.

## Проверка настоящим Chromium

Использовались Electron 45.0.0 / Chromium 156.0.8078.48 и изолированный временный профиль. В ограниченной среде применялся существующий тестовый runner, подменяющий только блокировку второго экземпляра приложения. CSP, CORS, проверка сертификатов и проверка формата шрифта оставались включены.

Прямой живой просмотр в Electron ограничен сетью среды: без её прокси получен `ERR_NAME_NOT_RESOLVED`, через прокси для HTTPS — `ERR_CERT_AUTHORITY_INVALID`. Поэтому успешная загрузка живой страницы целиком в Electron **не заявляется**. Получение HTML/TTF через curl и локальное воспроизведение — разные проверки.

В локальном воспроизведении использованы **фактически скачанный TTF и исходный inline CSS страницы**; заменён только адрес ресурса на тот же локальный origin, что и документ:

| Проверка | Обычная вкладка | Приватная вкладка |
| --- | --- | --- |
| Ответ TTF | 200 | 200 |
| `document.fonts.load('24px Monomakh', 'Библиотека')` | 1 загруженное лицо | 1 загруженное лицо |
| CDP: фактически отрисованный шрифт заголовка | Monomakh Unicode | Monomakh Unicode |
| PostScript-имя | MonomakhUnicode | MonomakhUnicode |
| Пользовательский веб-шрифт / число глифов | true / 27 | true / 27 |

Этот файл декодируется Chromium и применяется к кириллице. Сам MIME `application/octet-stream` не помешал загрузке в этом воспроизведении. Отличие CSS-псевдонима `Monomakh` от внутреннего имени `Monomakh Unicode` корректно. Ошибка OTS в проверке успешного воспроизведения не наблюдалась.

Во втором локальном воспроизведении тот же TTF отдавался с другого origin без ACAO. В обеих вкладках CDP зарегистрировал ошибку ресурса `Font`: `corsErrorStatus.corsError = MissingAllowOriginHeader`, `net::ERR_FAILED`. `document.fonts.load` завершился `NetworkError`, а фактически отрисованным шрифтом стал системный DejaVu Serif. Это воспроизводит нарушение CORS, без отключения защиты или предположения о повреждённом TTF.

## Исправление и обход

Для просмотра страницы следует использовать **`https://biblioteka33.ru/?p=172`**: документ и объявленный шрифт тогда имеют один origin. В браузер добавляется явное действие открытия текущей HTTP-страницы по HTTPS; адрес и выбор пользователя остаются видны.

На сервере сайта правильны следующие варианты:

1. Настроить постоянное перенаправление HTTP на HTTPS, сохраняя путь и query-параметры.
2. Использовать в `@font-face` относительный к origin адрес `url('/f5/monomakh.ttf')`. Тогда и HTTP-, и HTTPS-документы обращаются к шрифту своего origin. Важно, чтобы сервер затем не перенаправлял только HTTP-файл шрифта на HTTPS, снова создавая различие origin.
3. Если шрифт намеренно выдаётся с другого origin, настроить разрешающий CORS-заголовок на сервере ресурса. Браузер не должен дописывать его за сервер или отключать проверку CORS.

Принудительная замена шрифта на всех сайтах, отключение CORS/TLS и изменение содержимого страницы для этого не нужны.

## Повторение диагностики

`node scripts/site-font-diagnostics.mjs 'https://biblioteka33.ru/?p=172' artifacts/site-font-diagnostics`

Скрипт запускается вручную, использует временный профиль, проверяет обычную и приватную вкладки и сохраняет сведения о CSS/font-ответах, ошибках сети, FontFaceSet, вычисленных и фактически отрисованных шрифтах. Если headless renderer возвращает изображение, сохраняется скриншот. `SOUL_EXECUTABLE` задаёт альтернативный тестовый исполняемый файл. `SOUL_DIAGNOSTIC_ENV_PROXY=1` явно разрешает прокси из `HTTPS_PROXY` только для временной диагностической сессии; этот режим не меняет настройки рабочего профиля.

Детерминированная проверка общих сценариев загрузки шрифтов и сохранения границы CORS: `node scripts/site-fonts-smoke.mjs`. Скачанный TTF, полные HTML, ответы и скриншоты в исходный репозиторий не добавляются.

## Обновление 1.0.2: режим совместимости шрифтов

Диагностика выше остаётся в силе: корневая причина — различие origin между `http://biblioteka33.ru/?p=172`
и `https://biblioteka33.ru/f5/monomakh.ttf`, у которого нет `Access-Control-Allow-Origin`.

В 1.0.2 у пользователя появился выбор, которого не было в 1.0.1:

- **Совместимость шрифтов включена (по умолчанию).** Для ответов с `resourceType === 'font'`
  браузер снимает только требование `Access-Control-Allow-Origin`. CSP `font-src`, CORP,
  `Cross-Origin-Resource-Policy` и запреты, объявленные политикой сайта, по-прежнему действуют —
  это видно в §1.3 аудита движка.
- **Совместимость выключена.** Действует строгая проверка Chromium: страницу нужно открывать по
  `https://biblioteka33.ru/?p=172`, как описано выше.

Серверные исправления (постоянный редирект на HTTPS, относительный `url('/f5/monomakh.ttf')`,
разрешающий CORS-заголовок) остаются правильным решением: они работают в любом браузере и не
зависят от настройки. Клиентский режим — это совместимость, а не исправление чужой конфигурации.
