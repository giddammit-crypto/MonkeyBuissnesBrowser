# Вуду ИИ: инженерный аудит и обновление агента

Дата: 28 октября 2026 года. Исходная ревизия: `244ee25a310564524af85ded4c9566c0d4cf7e18`.

## Область и метод

Проверены агентный цикл, вызовы инструментов, работа с xkiro, управление вкладками и DOM, файловые операции, IPC, интерфейс чата и связанные ограничения безопасности браузера. Работу разделили между шестью экспертными ролями: ведущий ИИ разработчик, ведущий разработчик браузера, ведущий дизайнер приложений, руководитель разработки, тестировщик и full stack инженер. Названия ролей не означают участие сотрудников Google.

Основа выводов — исходный код, независимое ревью изменений и автоматические проверки. Это не независимый внешний пентест и не подтверждение работы каждого сайта. Номера строк ниже относятся к **исходной ревизии**, чтобы находки можно было воспроизвести после изменения файлов. В разделе проверки отдельно указано, что фактически запускалось; непроверенные сценарии не считаются пройденными.

## Вывод

В исходной версии уже существовал настоящий цикл model → tool → observation → model. Однако лимит в пять обращений к модели, неограниченные пакеты вызовов, слабая проверка аргументов, отсутствие остановки, отсутствующее чтение файлов и несколько ложных сообщений об успехе мешали сложным задачам. Обнаружены также встроенный API credential и опасное исключение из проверки TLS.

Обновление развивает существующий агент, добавляет отмену, более длинные контролируемые сценарии, чтение и список файлов, дополнительные действия браузера и улучшает восстановление после ошибок. Термин «полный контроль» по-прежнему нельзя понимать как универсальную автоматизацию всех сайтов, операционной системы или системных диалогов.

## Архитектурные границы, которые сохранены

1. `main.ts:83–90` проверяет ID доверенного shell WebContents, main frame и точный адрес `app://shell/index.html` перед привилегированными IPC. Обычная страница не получает право вызывать эти handlers лишь из-за похожего URL.
2. Shell/assistant и страницы используют `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webSecurity: true`; shell navigation и новые окна блокируются. Произвольный `execute_script` выполняется в странице, а не как Node.js shell.
3. Markdown ответа отрисовывается React как текст/структура; ссылки ограничиваются HTTP(S). Не добавлена загрузка непроверенного HTML в привилегированный shell.
4. `JsonStore` пишет настройки атомарно в файл с режимом `0600`, каталог создается с `0700`. Это контроль доступа ОС, **не шифрование ключей**. Ключи находятся в настройках и доступны доверенному UI; отдельного credential vault эта версия не вводит.
5. Содержимое прочитанных страниц/файлов отправляется настроенному внешнему AI endpoint. Приватная вкладка не означает локальную обработку ИИ. Список вкладок и некоторые инструменты могут включать приватные вкладки. Пользователь должен учитывать это при запросе анализа личных данных.

## Оставшиеся риски и следующий этап

- Отозвать ранее опубликованный ключ у xkiro. Ни удаление из `main`, ни маскирование UI не отменяет компрометацию в старой истории и копиях репозитория.
- Подтвердить поддерживаемые провайдером модели и реальные tool-calling контракты на живом endpoint с отдельным тестовым ключом. Не использовать опубликованный credential для такой проверки.
- Внедрить OS credential store и миграцию plaintext ключей, если продукт требует шифрования at rest. Не хранить секреты в Git.
- Добавить отдельную политику обработки приватных вкладок и чувствительных полей. Instruction-level defense от prompt injection не заменяет проверку разрешений на уровне инструментов.
- Файловое API намеренно не является песочницей против злонамеренного локального пользователя. Локальные hardlink/reparse-point и race сценарии требуют проверки по ОС; для строгой модели изоляции нужны dirfd/openat-подобные примитивы, разрешенные пользователем каталоги и платформенные тесты.
- Отмена предотвращает последующие шаги и прерывает поддерживаемые ожидания, но не отменяет уже отправленную форму, клик или созданный файл. Зависший JavaScript может продолжать работу в renderer после тайм-аута.
- Сложные сайты требуют browser-level integration tests с настоящим Electron: SPA, textarea/select/contenteditable, iframe, всплывающие окна, навигация во время отмены, hibernated/crashed tabs, неанглийские метки и сетевые сбои.
- Системные VPN, синхронизация, подписанные обновления и полная совместимость Chrome extensions не становятся реализованными от этого аудита. Их статус остается в `PLATFORM_FEATURE_STATUS.md`.
