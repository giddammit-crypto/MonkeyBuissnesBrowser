# Аудит движка и встроенных инструментов — 1.0.1

Дата: 2026-11-05. Проверены исходники браузера и официальный Linux ASAR версии 1.0.0 как неизменяемая база для подготовки 1.0.1. Этот документ не является утверждением о полной проверке всего Chromium, всех сайтов или всех расширений Chrome Web Store.

## Архитектура и границы совместимости

Веб-вкладки используют Chromium из Electron, `WebContentsView` и отдельную постоянную сессию `persist:northstar-default`. Приватные вкладки используют другую сессию. Оболочка, reader mode и веб-страницы имеют разные роли; ограничения внешней страницы нельзя исправлять отключением `webSecurity`, sandbox, CSP или CORS. В конфигурации обычных веб-вкладок включены `contextIsolation`, `sandbox`, `webSecurity`, запрещён `allowRunningInsecureContent`.

Проверка браузера включает три разных слоя: обработку браузером навигации/разрешений/сессий; работу Blink/Chromium с реальными HTML/CSS/шрифтами; доступность внешнего сайта, его CSS и файлов шрифтов. Например, корректный ответ HTTP 200 сам по себе не доказывает, что выбран нужный шрифт: нужны загрузка FontFace, подходящий Unicode-диапазон и фактический выбор гарнитуры. Заблокированный рекламный ресурс и сломанный URL файла шрифта требуют разных исправлений.

Основные источники: [BrowserController](../src/main/tabs/BrowserController.ts), [site policy](../src/shared/sitePolicy.ts), [page preload](../src/preload/page-preload.ts), [ограничения платформы](PLATFORM_FEATURE_STATUS.md).

| Инструмент | Подтверждённая реализация | Граница поддержки / что проверять |
|---|---|---|
| Локальные расширения Chrome | `LocalExtensionManager`: распакованная папка, проверка manifest MV2/MV3, согласие пользователя, до 30 расширений, сохранение путей и восстановление | Приём MV3 manifest не означает поддержку всех MV3 API. Нет установки CRX/Web Store и автоматического обновления. Только обычная сессия, `allowFileAccess: false`. Каталог должен оставаться на диске |
| Блокировка рекламы/трекеров | `FilterEngine` + `SessionAdBlock`: хосты, ограниченные path-правила, исключения для сайтов, счётчики, отдельная приватная политика; YouTube page policy gate | Это собственный ограниченный движок правил, не полная реализация синтаксиса uBlock/EasyList. Хостовые правила могут блокировать общие функции сайта. Требуется отключение для конкретного сайта при диагностике |

| Click & Clean | Выбор категорий, очистка данных Electron-сессии и внутренних хранилищ | Оценка освобождённого места ограничена реально измеряемым дисковым кэшем; отдельные категории имеют разные семантики. В 1.0.1 исправляются preflight, CacheStorage и оценка размера |
| Reader / заметки | Режим чтения, настройки гарнитуры/размера/темы, работа со статьёй и заметками | Веб-шрифт исходного сайта и шрифт reader mode — разные вещи; стили reader mode не исправляют отсутствующий ресурс сайта |
| Медиа / PiP / загрузки | Нативные загрузки, обнаружение медиа, мини-плеер/нативный PiP, специализированные команды YouTube/VK/Pinterest | Доступность медиа зависит от сайта, cookies и внешнего инструмента загрузки; универсальное воспроизведение DRM или скачивание любого потока не гарантируется |
| Memory saver | Управление бюджетом сессии и спящими вкладками | Освобождение/восстановление вкладки требует проверки контекста, приватности, активного медиа и выбранного workspace |
| Voodoo AI | Выбор провайдера/модели, контекст страницы, файлы, быстрые действия, workflows | Сеть и сервер модели внешние. Валидный ключ не гарантирует успешный ответ. Timeout, abort, malformed response и превышение размера должны различаться |

## Полезные дополнения для 1.0.1

Вместо добавления ещё одного универсального расширения выбраны две небольшие встроенные возможности, которые непосредственно решают запросы пользователя:

1. **Диагностика шрифтов страницы** — состояние `document.fonts`, объявления гарнитур и ошибки/недоступность информации без отключения защиты Chromium. Это помогает отличить ошибку браузерной политики от отсутствующего файла, неподходящего glyph coverage или внешнего CSS. Функция не должна обещать определение фактически отрисованного glyph по одному `font-family`.
2. **Копирование ссылки без рекламных меток** — удаление известного ограниченного списка `utm_*`, `fbclid`, `gclid` и аналогичных идентификаторов, с сохранением функциональных параметров и fragment. Это самостоятельная команда: автоматическая модификация каждого перехода могла бы ломать сайты и авторизацию.

В рабочем дереве реализации: [PageFontInspector](../src/main/services/PageFontInspector.ts), [cleanLink](../src/shared/cleanLink.ts). Статус их итоговой сборки и runtime-проверок фиксируется в релизном отчёте, а не выводится из наличия файла.

Дополнительные кандидаты на отдельные будущие задачи: отображение неподдерживаемых API/ошибок каждого локального расширения; обновляемые подписанные наборы фильтров с откатом; менеджер разрешений по origin. Для первых двух требуется отдельная модель обновления и воспроизводимые тестовые расширения. Новая синхронизация, системный VPN и автообновления не заявляются реализованными.

## Проверенные регрессии и приоритеты

Параллельный аудит для 1.0.1 выявил и направил в исправление следующие конкретные классы ошибок: несогласованная принадлежность вкладки workspace при дублировании/восстановлении/переносе; неверная классификация обрыва тела ответа AI; очистка с частичным результатом при недоступном password vault; пропущенный CacheStorage при очистке Service Workers; завышенная оценка освобождённого места; Enter во время IME-композиции; подсказка bang-search с неправильным провайдером; URL-дедупликация с потерей регистра пути/параметров.

Эти исправления проверяются владельцами изменений и общей релизной проверкой. Ограничения платформы из таблицы не объявляются устранёнными только на основании прохождения unit-тестов.

Непосредственно в рамках данного аудита выполнено:

```text
npx vitest run tests/unit/extensions-lifecycle-regressions.test.ts \
  tests/unit/adblock.test.ts tests/unit/browsec.test.ts \
  tests/unit/page-adblock-policy.test.ts tests/unit/youtube-adblock-policy.test.ts
5 files passed; 32 tests passed.
```

Это unit-проверки lifecycle/валидации/политик с тестовыми зависимостями. Они не доказывают совместимость стороннего расширения в реальном Electron и не заменяют тесты на живом сайте.

## REA: фактический запуск и ограничение среды

Использован CLI `rea-agents` **6.8.0** из доверенного рабочего каталога вне проекта. MCP-сервер не регистрировался; native-анализаторы и setup не запускались. Объект — официальный опубликованный ASAR 1.0.0:

```text
/tmp/monkey-official-deb/opt/soulm8te/resources/app.asar
SHA-256 c255cb74ec73504bff572b2af7a77d0e4749997149d43e4b0bc3aa0152a8267a
```

После чтения CLI help выполнена ограниченная команда статического анализа с тремя точно выбранными файлами, без исполнения кода приложения:

```bash
node <rea-package>/scripts/rea.mjs analyze-javascript-application \
  /tmp/monkey-official-deb/opt/soulm8te/resources/app.asar \
  --source-path dist/main/services/extensions/LocalExtensionManager.js \
  --source-path dist/main/services/adblock/FilterEngine.js \
  --source-path dist/main/services/browsec/BrowsecService.js \
  --max-semantic-nodes 10000 --max-semantic-nodes-per-file 4000 \
  --max-semantic-unknowns 2000 --max-heap-mb 512 \
  --analysis-timeout-ms 30000 --json
```

**Результат: exit 1, `capability_unavailable`, `unsupported_provider`.** Перед запуском изолированного JS-анализатора REA требует проверку владельца процесса через procps `ps`. В этой среде команда `ps -axo pid=,ppid=,pgid=,uid=,stat=,command=` завершается `fatal library error, lookup self`. Упрощать контроль процессов, подменять `ps` или продолжать через нештатный внутренний API не предпринималось.

REA сохранил частичное наблюдение `ev_baa8899c5b017ff628b1cf2ceb16326812525e4783ae5fedc1496afefdadddcf`. Инвентаризировано 5310 релевантных файлов; выбрано 3; 5307 вне области; прочитано 37629 байт. **Разобрано 0 JS-файлов, пропущено 3.** Нули в summary/findings отражают незавершённый анализ, а не отсутствие ошибок или прохождение аудита.

Компактная точная выписка результата, параметров и ограничений сохранена в [REA_1.0.0_BASELINE_PARTIAL.json](REA_1.0.0_BASELINE_PARTIAL.json). Полный JSON с inventory (53 912 307 байт) и stderr сохранены во временном каталоге `rea-audit` вне репозитория. Это наблюдение относится к ASAR 1.0.0; оно не удостоверяет артефакт 1.0.1. Для завершения REA нужен Linux runner с рабочим procps, повтор того же анализа, затем проверка нового ASAR и его отдельного SHA-256.

Основной функциональный аудит выполнен по доступным исходникам и целевым тестам, независимо от остановившегося статического REA-прохода. Полная совместимость с Google Chrome, полный аудит Chromium и отсутствие всех ошибок не утверждаются.

## Повторяемый REA-проход на GitHub

Workflow Ubuntu release выполняет тот же ограниченный проход трёх выбранных модулей на собранном ASAR 1.0.1 в обычной Ubuntu 24.04 с procps. Evidence сохраняется как artifact `rea-packaged-plugin-audit`, compact summary/coverage печатается в лог. Публикация допускается только после успешного CLI и разбора всех трёх файлов без skipped. Даже успешный проход не означает полного анализа приложения: остальные модули и динамические связи остаются вне подтверждённого покрытия. Фактический итог следует проверять по конкретному запуску workflow.
