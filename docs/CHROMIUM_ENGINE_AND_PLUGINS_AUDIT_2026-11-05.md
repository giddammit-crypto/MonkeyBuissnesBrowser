## 1. Шрифты: почему «шрифт не отображается»

### 1.1. Что известно про страницу

Страница отдаётся старым CMS-шаблоном, где типографика задана через `@font-face` с семейством
`Monomakh` и декоративными альтернативами (Monotype Corsiva-подобный курсив) в списке `font-family`.
Это ровно тот класс страниц, где текст «есть», а шрифт «не тот»: браузер молча рисует запасной шрифт.

### 1.2. Три реальные причины (проверены кодом и фикстурами)

| Класс | Механика | Как выглядит для пользователя | Что было в коде до итерации |
|---|---|---|---|
| **A. Запрос не доходит** | фильтр рекламы (`/ads/`, `/pagead/`, `/adserver/`), CSP сайта, 404/403, `net::ERR_*` | шрифт «пропал», текст запасной | фильтр уже не блокирует `font`/`stylesheet` по путевым эвристикам, но причину никто не показывал |
| **B. CORS/CORP** | шрифт лежит на другом хосте/CDN без `Access-Control-Allow-Origin`, либо с `Cross-Origin-Resource-Policy: same-origin` | шрифт не применяется, в консоли — только `blocked by CORS policy` | **не обрабатывалось** (проверялось тестом как «граница сохраняется») |
| **C. Шрифта нет в системе** | `font-family: "Monotype Corsiva", "Monomakh"` без веб-шрифта: на Linux этих гарнитур нет | вместо курсива/акцента — обычный сериф | не диагностировалось |

Третья, «неудобная» причина: **Chromium никогда не сообщает об этом в UI**. Ошибка живёт в DevTools
(консоль/Network) и в `document.fonts`. Поэтому «проверка загрузки шрифтов» без сбора сетевой
телеметрии из main-процесса принципиально неполна.

### 1.3. Что реализовано

1. **`src/shared/fontCompat.ts`** (чистые функции, 100 % unit-тестов)
   * парсинг `font-family` с кавычками и запятыми;
   * таблица подстановок Windows/macOS → установленные аналоги (Times New Roman → Liberation Serif,
     Monotype Corsiva → URW Chancery L/Z003, Calibri → Carlito, Consolas → Inconsolata, …);
   * `buildFontSubstitutionCss()` — генерирует **только** `local()`-источники, никогда `url()`:
     подстановка не может сходить в сеть и не «изобретает» шрифт, которого нет;
   * `relaxFontResponseHeaders()` — снимает устаревшее CORS-ограничение **только** у ответов
     `resourceType === 'font'` и **только** когда политика пользователя это разрешает;
   * `classifyFontConsoleMessage()` — превращает сообщения Chromium (`OTS parsing error`,
     `Failed to decode downloaded font`, `CORS policy`, `Content Security Policy`, `net::ERR_*`)
     в понятные причины;
   * `sanitizeFontUrl()` — в отчёт попадает только хост+путь, без query/credentials/фрагмента.

2. **`src/main/services/SiteFontMonitor.ts`** — ограниченный (32 записи на страницу, 64 страницы)
   журнал доказательств: блокировки фильтром, `onErrorOccurred`, HTTP ≥ 400, консольные сообщения.
   Записи дедуплицируются и обрезаются до 200 символов.

3. **`PageFontInspector`** расширен: проба в isolated world 999 теперь измеряет доступность каждого
   семейства через canvas-метрики против двух генерических фолбэков (иначе `document.fonts.check()`
   врёт: для незнакомого семейства возвращает `true`). Результат — `familyAvailability` и
   `missingFamilies`.

4. **UI** (`FontDiagnosticsModal`): новый блок «Почему шрифт не отображается» (тип причины, хост+путь,
   текст ошибки), блок «Шрифты, которых нет в системе» с кнопкой **«Подставить похожие»**
   (`browser:apply-font-substitutions`) и счётчик снятых CORS-ограничений.

5. **Настройка** «Совместимость шрифтов сайтов» (`settings.fontCompatibility`, по умолчанию включена).

### 1.4. Как проверить на самой странице

1. Открыть `http://biblioteka33.ru/?p=172`.
2. Меню страницы → «Шрифты страницы».
3. Смотреть блок «Почему шрифт не отображается»:
   * `Нет в системе` → нажать «Подставить похожие» и перезагрузить страницу;
   * `Политика CORS` + «снято ограничение CORS у N ответов» → шрифт уже загружен, перезагрузка не нужна;
   * `Ответ сервера` (404/403) → проблема на стороне сайта, браузер бессилен — это видно сразу;
   * `Файл шрифта повреждён` (`OTS parsing error`) → сервер отдаёт битый/подменённый файл.
4. `scripts/site-font-diagnostics.mjs` (opt-in) сохраняет полный отчёт по живой странице:
   `node scripts/site-font-diagnostics.mjs https://biblioteka33.ru/?p=172`.

### 1.5. Границы заявления

* Измерение доступности шрифта — **эвристика** (canvas-метрики), а не доказательство отрисовки глифов.
* Подстановка срабатывает только при наличии установленного аналога; при его отсутствии браузер
  сохраняет прежний фолбэк (текст не исчезает).
* Снятие CORS — совместимость, а не «дыра»: ослабляется только ответ со шрифтом, скрипты/стили/медиа
  остаются под строгой политикой. Отключается тумблером.

## 2. Движок Chromium: что проверено

### 2.1. Роли и выводы

**Ведущий разработчик Google Chrome.** Пайплайн навигации и изоляция процессов соответствуют модели
Chromium: `WebContentsView` на вкладку, отдельная `Session` для приватного профиля, preload в
sandbox-режиме, isolated world 999 для служебных проб, `will-attach-webview` заблокирован,
`setWindowOpenHandler` с контролем popup. Проблема не в движке, а в том, что часть ошибок подресурсов
(шрифты) не имеет пользовательского представления. Исправлено сбором телеметрии в main-процессе.

**Разработчик Chromium (Blink/сеть).** Найденные несоответствия эталонному Chromium:
1. `onHeadersReceived` не модифицировался для шрифтов → поведение строже Chrome ≤ 2011 и Firefox.
2. `plugins: true` отсутствовал → PDF-ссылка не открывалась во встроенном просмотрщике.
3. XSLT-инструкции `xml-stylesheet` игнорировались без какого-либо уведомления (Chromium 158 удаляет
   libxslt: [Chrome 158, 17.11.2026](https://www.streamingmeme.com/articles/google-sets-chrome-xslt-support-removal-for-november-2026)).
Все три устранены.

**Ведущий разработчик ПО Google.** Архитектурно новые возможности добавлены аддитивно
(новые модули + точки подключения), без переписывания `BrowserController`: сервисы
`SiteFontMonitor`, `XsltSupport`, `XsltPageProbe`; сетевые хуки встроены в существующий
`configureSession`, состояние очищается на `did-start-navigation` и `destroyed`.

**Фулстек-инженер.** IPC расширен одним каналом (`browser:apply-font-substitutions`) и одной
настройкой; XSLT не добавляет IPC-поверхности для страниц вообще — трансформация идёт из main,
страница не может запросить произвольный URL. CSP/CORS-границы сайта при этом не ослабляются.

**Тестировщик.** Покрытие: 44 новых unit-теста (XML-парсер, XPath, трансформации, политика XSLT,
шрифтовая совместимость, монитор), 2 новых e2e (`xslt-smoke`, `pdf-viewer-smoke`) и расширенный
`site-fonts-smoke` (включая проверку строгого режима после отключения тумблера). Ограничение:
e2e в этой песочнице не запускаются (нет бинарника Electron).

**Ведущий дизайнер.** В диагностике шрифтов теперь виден «путь пользователя»: причина → объяснение →
действие. Кнопка подстановки не обещает невозможного (если аналогов нет — прямо говорит об этом).
XSLT-страница получает ненавязчивый бейдж `XSLT` на 9 секунд вместо модального окна; ошибка XSLT —
тонкая полоса внизу вместо «белого экрана».

### 2.2. Карта слоёв (актуальная после изменений)

```
main process
├── BrowserController            вкладки, сессии, навигация, права, загрузки
│   ├── configureSession()       webRequest: блокировка, cookies, UA/CH, headers
│   │   ├── onBeforeRequest      реклама; журнал заблокированных шрифтов
│   │   ├── onBeforeSendHeaders  UA/Client Hints, DNT/GPC, cookie-скоуп
│   │   ├── onHeadersReceived    mainFrame XML-детект + CORS/CORP для font
│   │   ├── onErrorOccurred      (new) доказательства по шрифтам
│   │   └── onCompleted          (new) HTTP-статусы шрифтов
│   ├── SiteFontMonitor          bounded evidence log
│   ├── XsltSupport              PI → fetch → transform → HTML
│   └── PageFontInspector        isolated world 999, canvas-метрики
```

### 2.3. Остающиеся ограничения движка (честно)

* Widevine CDM в Electron не поставляется → DRM-видео (Netflix, ivi, Okko) не воспроизводится.
* H.264/AAC зависят от сборки Electron; в официальных сборках присутствуют.
* Service Worker/cache storage не вычищаются по расписанию (только вручную через очистку данных).
* Сетевой стек не поддерживает HTTP/3 через прокси-туннель (ограничение Chromium).

## 4. Аналог XSLT Browser Support

### 4.1. Почему свой движок, а не libxslt-wasm

Расширение-референс компилирует libxslt в WebAssembly. Для десктопного браузера это означает
непроверяемый бинарный артефакт ~2–4 МБ и ещё одну поверхность атаки — ровно та причина, по которой
Chromium избавился от libxslt. В репозитории `LICENSE = MIT`, а доступные npm-реализации
(`xslt-processor`) распространяются под LGPL‑3.0, то есть требуют иной модели линковки.

Поэтому реализован собственный XSLT 1.0-процессор на TypeScript: без WASM, без новых зависимостей,
с детерминированным поведением и полным покрытием unit-тестами.

### 4.2. Архитектура

```
src/services/xslt/
├── xml.ts          XML 1.0 парсер + дерево + сериализатор (без внешних сущностей)
├── xpath.ts        XPath 1.0 (оси, предикаты, функции, переменные)
├── processor.ts    компиляция xsl:stylesheet и исполнение шаблонов
└── XsltSupport.ts  PI → политика → fetch → include/import → transform
src/main/services/XsltPageProbe.ts   isolated-world скрипты (проба, применение, ошибка)
```

Поток:

1. `onHeadersReceived` помечает mainFrame-ответы с XML MIME (`application/xml`, `*+xml`, `text/xml`).
   `image/svg+xml` и `text/html` исключены.
2. `dom-ready` → проба в world 999 читает `<?xml-stylesheet?>` (только `text/xsl`/`application/xml`/`text/xml`)
   и сериализует документ (лимит 4 МБ).
3. `XsltSupport` резолвит href, проверяет **тот же origin**, ограничивает размер стиля 1 МБ,
   разворачивает `xsl:include`/`xsl:import` (≤16 штук, глубина 8, защита от циклов), кеширует на 5 минут.
4. Трансформация → HTML/XML/text; результат пишется в документ через `document.open/write/close`
   (тип документа становится `text/html`, URL в адресной строке сохраняется).
5. Ошибка → тонкая полоса с текстом причины вместо «стены тегов».

### 4.3. Что поддерживается

* Шаблоны: `match`-паттерны (включая `/`, `//`, предикаты), приоритеты, `mode`, встроенные шаблоны.
* Инструкции: `apply-templates`, `call-template`, `with-param`, `param`, `variable`, `for-each` + `sort`,
  `if`, `choose/when/otherwise`, `value-of` (+`disable-output-escaping`), `copy`, `copy-of`,
  `element`, `attribute`, `text`, `comment`, `processing-instruction`, `number`, `message`, `output`.
* Выражения: location paths, оси `child/descendant(-or-self)/self/parent/ancestor(-or-self)/attribute/
  following-sibling/preceding-sibling/following/preceding`, предикаты, арифметика, `div`, `mod`, `|`,
  сравнения по правилам XPath 1.0, функции `last position count name local-name namespace-uri string
  number concat starts-with contains substring-before substring-after substring string-length
  normalize-space translate sum floor ceiling round boolean not true false generate-id`.
* Упрощённые таблицы стилей (`<html xsl:version="1.0">`).
* Методы вывода `html` (void-теги, raw-text `script/style`), `xml` (декларация, самозакрытие), `text`.

### 4.4. Что не поддерживается (и почему это безопасно)

| Не поддержано | Причина |
|---|---|
| `document()`, `key()`, `xsl:key` | сеть/произвольные файлы: исключено политикой, ошибка с текстом |
| `xsl:script`, extension functions | исполнение JS в контексте браузера |
| Внешние DTD/сущности | XXE отключён на уровне парсера (внешние сущности не читаются) |
| EXSLT (`regexp`, `math`, `date`) | нет в эталонном поведении Chromium; вернём отдельным слоем при необходимости |
| `xsl:attribute-set`, `namespace-alias`, `decimal-format`, `xsl:apply-imports`, `next-match` | редкие в веб-стилях фичи; `apply-imports`/`next-match` дают явную ошибку |
| `strip-space`, `xml:space`, отступы `indent` | влияют только на косметику вывода |
| Полный `xsl:number` (`format="a/i/I"`) | поддержан уровень `single/any/multiple` с форматом `1` |

Стили, использующие неподдерживаемую инструкцию, **не** дают молчаливый пустой результат: они
показывают причину в полосе ошибки.

### 4.5. Тесты

| Файл | Что проверяет |
|---|---|
| `tests/unit/xslt-xml.test.ts` | парсер (CDATA, PI, сущности, namespace, лимиты), XPath-оси/функции, запрет `document()`/`key()` |
| `tests/unit/xslt-transform.test.ts` | RSS→HTML, сортировки, `choose`, переменные, `with-param`, `mode`, приоритеты, `copy-of`, AVT, `disable-output-escaping`, text/xml-вывод, simplified stylesheet |
| `tests/unit/xslt-support.test.ts` | определение MIME, разбор PI (CSS игнорируется), primary vs alternate, same-origin политика, include/циклы, кеш, размеры, сообщения об ошибках |
| `scripts/xslt-smoke.mjs` | реальный Electron: рендер ленты, сохранение URL, кеш стиля, нетронутый plain-XML, блокировка `document()`, выключение настройкой |

## 6. Приоритеты следующей итерации

1. **EXSLT-слой** (`regexp:match`, `math:*`) — самые частые «почти работающие» стили.
2. **`xsl:attribute-set` и `xsl:import` с precedence** — для больших корпоративных таблиц.
3. **Полный `xsl:number`** (`a`, `i`, `A`) и `format-number`.
4. **Диагностика шрифтов по требованию**: кнопка «Обновить» уже есть, добавить автоповтор
   «шрифт не применился после загрузки» (сейчас требует ручного открытия панели).
5. **PDF-аннотации/масштаб**: сейчас используется штатный просмотрщик Chromium без кастомизации.

## 7. Сквозной аудит браузера, 5 ноября 2026 (итерация 1.0.2)

Проверены слои, которые пользователь перечислил явно: вкладки, адресная строка, ИИ, очистка,
настройки, несколько окон. Для каждого пункта указано, что именно проверено и что изменено.

### 7.1. Иконка «Click & Clean»

Раньше на панели стояла тонкая кисть из набора lucide (`broom`: ручка и короткий скошенный ворс).
На 18 px она читается как случайный глиф. Добавлен `src/renderer/BroomIcon.tsx`: ручка, обойма и
веер из четырёх щетинок плюс перевязка. Иконка используется в трёх местах — кнопка панели (18 px),
пункт главного меню (16 px) и окно очистки (28/22/16/13 px), — поэтому «веник» виден везде, где
запускается очистка. Стиль совпадает с остальными иконками: сетка 24×24, `stroke-width` 1.8,
круглые окончания, `currentColor`.

### 7.2. Что исправлено

| Область | Дефект | Правка |
|---|---|---|
| Масштаб (`Ctrl +/-`) | `NaN`, `0` или значение вне шкалы (например, сайт выставил 0.1) отправляли следующую ступень в крайнее положение — «+» прыгал на 500 % | `getNextZoomFactor` проверяет конечность и положительность, затем ограничивает значение диапазоном 0.25–5.00 |
| Адресная строка | запрос `?` без текста превращался в поиск пустой строки | возвращается подсказка «Введите поисковый запрос после «?»» |
| Адресная строка | полное имя хоста с точкой на конце (`example.com.`) уходило в поиск | добавлена поддержка FQDN-формы |
| XSLT + несколько окон | `webRequest`-хуки ставит тот контроллер, который создал сессию, а вкладка может жить в другом окне: XML-ответ не находился, преобразование не применялось, счётчик ослабленных шрифтовых ответов был свой у каждого окна | `xmlDocuments`, `xsltApplied`, `relaxedFontResponses` стали статическими (на процесс), доступ идёт через `BrowserController.*` |
| XSLT | неудачный `executeJavaScriptInIsolatedWorld` (страница ещё грузится) навсегда помечал документ обработанным, и стиль больше не применялся | метка снимается, следующий `dom-ready` повторяет попытку; пустой probe тоже не блокирует повтор |
| Производительность | на каждой строке консоли сайта выполнялись до шести регулярных выражений — на «болтливой» странице это тысячи вызовов | дешёвый предфильтр по подстрокам (`font`, `woff`, `ttf`, `otf`, `ots `) по первым 400 символам |
| Совместимость шрифтов | решение 1.0.1 («только HTTPS-адрес, CORS не трогаем») не помогало пользователю, который продолжает открывать HTTP-страницу | добавлен явный режим совместимости (включён по умолчанию, отключается), CORS-ослабление только для `resourceType === 'font'`, CSP/CORP/исключения Chrome сохраняются — см. §1 |

Новые тесты: `tests/unit/zoom.test.ts` (+1 блок), `tests/unit/omnibox.test.ts` (+3 блока),
`tests/unit/site-font-compat.test.ts` (переписаны ожидания под режим совместимости и строгий режим),
`tests/unit/xslt-*.test.ts`.

### 7.3. Что проверено и оставлено как есть

* **Вкладки.** Создание, дублирование, перенос между окнами, отрыв в отдельное окно, закрепление,
  отключение звука, поиск по вкладкам, гибернация и восстановление сессии покрыты unit/Electron
  тестами; новых дефектов в этой итерации не найдено.
* **Адресная строка.** Подсказки (вкладки, популярные сайты, закладки, история, поиск), префиксы
  `g/ya/ddg/?`, локальные адреса и `.local`, IDN, запрет схем `javascript:`, `file:`, `data:` и
  адресов с учётными данными — поведение подтверждено тестами.
* **ИИ (Вуду).** Различение отмены, таймаута тела ответа и некорректного JSON, ротация ключей и
  запрет пометки ключа исчерпанным при сетевом сбое уже исправлены в 1.0.1; повторных правок не
  потребовалось.
* **Очистка.** Веник заменяет только иконку; логика (проверка хранилища паролей до удаления,
  CacheStorage вместе с Service Workers, измеренная оценка освобождённого кэша) не менялась.

### 7.4. Честные границы

* Electron-бинарник в среде этой итерации недоступен, поэтому e2e-скрипты (`xslt`, `pdf`,
  `site-fonts`, `release-ui`) здесь не запускались; они выполняются в CI на Ubuntu 24.04.
  Unit-набор и типизация обоих проектов пройдены локально.
* Поведение шрифта на живом `biblioteka33.ru` проверено по заголовкам ответов и по локальному
  воспроизведению (документ `http://`, шрифт `https://` без `Access-Control-Allow-Origin`), а не
  «на глаз» в GUI этой среды.
