## Учет этапов

`update_plan` обслуживается внутри сервиса, а не браузерным dispatcher. До 20 непустых этапов, до 300 символов каждый; `completed_steps` — целое число в пределах списка. Исходные этапы нельзя удалить, заменить или сбросить; уточнения добавляются в конец. Увеличение выполненной части требует нового успешного наблюдаемого действия после последнего подтверждения. Одно старое действие нельзя повторно использовать для закрытия нескольких этапов. Ошибка последнего внешнего действия не позволяет закрыть этап.

Это механическая проверка прогресса, а не доказательство смысловой полноты. Модель отвечает за правильную декомпозицию; успешный инструмент не доказывает, что найдено все требуемое. Простые диалоги не принуждаются к планированию. Если модель вообще не создала план, проверка незаконченных пунктов по плану не применяется; системная инструкция предписывает создавать его для составных задач.

По умолчанию доступно 24 раунда модели; программный `maxSteps` ограничен 48, общий бюджет действий — 48, включая обновления плана. Восстановление после обрезки и напоминания расходуют раунды. Отмена не откатывает уже совершенный эффект. Завершение по лимиту, блокировке и отсутствию прогресса отличается от успешного выполнения.

## Сопутствующий дефект сборки

У предыдущего коммита `14e6931` GitHub Actions verify, Linux и macOS packaging завершились успешно, но Windows packaging упал: `Icon must be at least 256x256 pixels, provided: 16x16` (run `40732458393`, job `122972093037`). Windows config указывал на ICO с единственным изображением 16×16. Теперь используется существующий PNG 512×512, который electron-builder преобразует в ICO; release-assets проверяет именно выбранный Windows источник и его минимальный размер. Это изменение конфигурации, без замены изображения. Прямой вызов установленного конвертера electron-builder прошел: создан ICO с максимальным изображением 256×256. Полная Windows сборка новой ревизии должна подтвердиться в GitHub Actions.

## Ограничения и дальнейшая проверка

Живой xkiro с новым пользовательским ключом не проверялся. Нельзя объявлять измеренное улучшение качества конкретной модели только по детерминированному провайдеру: тесты подтверждают поведение оркестратора и браузера при заданных ответах. Для оценки модели нужны отдельные повторяемые задания на реальном endpoint и ручная проверка полноты результата.

Сохраняются ограничения основного документа, файловых каталогов и размера 1 МиБ. Native dialogs, CAPTCHA, закрытый shadow DOM и сложные iframe могут требовать участия пользователя. Windows/macOS и экранный диктор этим изменением не проверялись. История и журнал ограничены по объему; это не постоянная база знаний и не автоматическое продолжение после перезапуска. Большие запросы с недостаточным контекстом завершаются явной ошибкой, а не бесконечным циклом.
