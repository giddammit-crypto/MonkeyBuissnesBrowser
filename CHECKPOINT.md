### Интеграция двух линий работы

1.0.2 вышла двумя независимыми наборами изменений. В 1.0.3 они объединены:

- **Эргономика вкладок (из 1.0.2):** активация по `MouseDown`, лазерная линия вставки при
  перетаскивании, тактильный захват, защита закреплённых вкладок, бейдж «Спит», эквалайзер
  звучащей вкладки, глушение по Ctrl+M, быстрые заметки, поиск по вкладкам, панель Вуду.
- **Веб-стандарты (эта линия):** совместимость веб-шрифтов и панель диагностики, встроенный
  PDF-просмотрщик, собственный XSLT 1.0 + XPath, веник в Click & Clean, исправления аудита.

### Исправления этой итерации

- **XSLT на фидах.** Chromium отдаёт `application/rss+xml` как plain text, поэтому в DOM нет
  пролога. Источник документа теперь читается через сессию вкладки (cookies, прокси, та же
  политика сертификатов), а результат подставляется через `Page.setDocumentContent` — `document.write`
  внутри XML-документа запрещён спецификацией. Ошибка больше не «тихая»: полоса с причиной.
- **Обновления (1.0.2 → 1.0.3).** Проверка обновлений больше не блокирует главный процесс:
  `gh auth token` вызывается асинхронно и только при 403/429 от GitHub API. Добавлен предел
  размера ответа API (1 МБ) в обеих транспортных ветках.
- **CI.** Каждый Electron smoke-скрипт публикует check-аннотацию с хвостом вывода при падении
  (`scripts/run-smoke-suite.mjs`), поэтому падение `test:e2e:features` теперь само объясняет причину.
- **Релизы.** `.tar.gz` — предпочтительный формат для встроенного обновления; workflow релиза
  публикует `.deb`, `.AppImage` и `SHA256SUMS`, поэтому `.tar.gz` для 1.0.3 загружается вручную
  тем же способом, что и для 1.0.2 (изменение workflow требует прав `workflows` у GitHub App).

Документы: `docs/RELEASE_1.0.3.md`, `docs/CHROMIUM_ENGINE_AND_PLUGINS_AUDIT_2026-11-05.md` (§7).

## 🛡️ Реализованный функционал и исправления безопасности v0.9.9

1. **Устранение ошибки «Этот браузер или приложение может быть небезопасным» (Google Accounts & BotGuard Compliance):**
   - **Стабильная идентификация Chromium 134:** Заголовок User-Agent и Client Hints (`NavigatorUAData`) согласованы с релизной версией Chrome 134 (`134.0.0.0`). Это исключило сбой валидации milestone-версий на серверах аутентификации Google Accounts (`accounts.google.com/v3/signin/rejected`), возникавший при отправке версии Chromium 156.
   - **Эмуляция нативных геттеров `[native code]`:** Реализован механизм `markNative` с WeakSet-кэшированием и патчем `Function.prototype.toString`. Геттеры свойств `navigator.userAgent`, `appVersion`, `platform`, `vendor`, `webdriver`, `userAgentData`, а также методы `window.chrome.csi`, `loadTimes`, `app` возвращают эталонный `[native code]`, успешно проходя интроспекцию Google BotGuard (`bg.js`).
   - **Запасной шлюз аутентификации (Escape Hatch):** В баннер помощи аутентификации встроена кнопка «Открыть в системном браузере», позволяющая мгновенно завершить вход в локальном окружении ОС при строгой политике Google Workspace.

2. **Безопасность демона Linuxsec и VPN-подсистемы:**
   - **Ограничение UNIX-сокета:** Разделение прав доступа сокета `/run/linuxsec/daemon.sock` (владелец root:linuxsec, права 0770/0660 с fallback 0600).
   - **Защита от инъекций сетевых команд:** Строгая валидация интерфейсов и IP-адресов/портов для nftables/iptables.
   - **Атомарный переход состояний VPN:** Состояние `connected` устанавливается исключительно после успешного применения правил kill switch и защиты от утечек IPv6.

3. **Безопасность системы обновлений (UpdateService Hardening):**
   - Скачивание обновлений ограничено белым списком доверенных HTTPS-хостов (`github.com`, `api.github.com`, `objects.githubusercontent.com`).
   - Защита от path traversal в именах загружаемых файлов релизов.
   - Автоматическая валидация SHA-256 контрольных сумм дистрибутивов.
